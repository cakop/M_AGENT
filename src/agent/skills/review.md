# 代码评审规范

当你需要 review 代码时，遵循以下规范：

1. **先读懂**：通读代码，理解它要做什么
2. **检查维度**：
   - 逻辑正确性（边界条件、空值、异常）
   - 代码质量（命名、重复、复杂度）
   - 安全性（输入校验、路径处理、命令执行）
   - 可维护性（注释、模块化）
3. **输出格式**：
   - 总评（1-2 句）
   - 问题列表（严重程度 + 位置 + 建议）
   - 亮点（如果有）
4. **不要**：不要只夸不挑毛病，不要改代码（只评审）
